# 最新财报三张表：面子、里子、底子

## 目标与范围

让没有财务基础的读者**只用三张表**读懂企业最新一次完整财报：

- **利润表＝面子**：报告期卖了多少、赚了多少，增长是否真实、利润有没有改善。
- **现金流量表＝里子**：利润有没有变成现金、钱流向哪里。**财务判断先看现金是否跟得上利润**；经营现金、扩张投入、融资借款不可混淆。
- **资产负债表＝底子**：截至期末有多少资产、欠多少债、股东还剩多少账面权益，能否抵御经营波动。资产负债表反映长期积累的经营与融资结果，**不等于仅由现金流决定**。

**只研究这三张报表及理解它们必不可少的附注**。不做 CEO、商业模式、企业文化、行业链、竞品、事件 Roadmap、未来预测、估值、股价、交易建议，也不自动改动其他 Skill 或网站。

## 第一步：获取「最新完整财报」

1. **优先官方原始资料**：美国上市公司查 SEC EDGAR 最新的适用 10-Q／10-K（包括财务报表及关键附注）；其他市场查交易所公告和公司投资者关系网站的正式季报、半年报、年报。先核对披露日、所对应**财务期末**、币种、单位、会计准则与审计／未审计状态。
2. **“最新”指截至执行时已正式披露、含完整三张表的最近一期**，不以旧年报、新闻摘要、预测数据或上次保存的报告冒充最新；披露了更新的盈利公告但尚无完整三表时，明确说明该公告不满足要求，使用最近一份有完整三表的正式披露，并交代局限。
3. **强制同比 + 环比，统一理解但不混淆期间与时点**：
   - **利润表**：以最新已公布单季度为主，依次找**本季 Q4 / 上季 Q3 / 去年同季 Q4**。同时显示「同比（本季与去年同季）」及「环比（本季与上一季）」；优先使用原始单季报表数据，无单季直接披露但可用合法累计差分时，明确计算来源。年报只披露全年且无法核实 Q4 单季时，不能把全年当 Q4；可退而比较**本年／上年／上上年全年**，年度变化列应标明「同比／上年同比」，**环比标为不适用／无可靠可比单季**，不能伪装成上一季度。
   - **现金流量表**：必须尽可能还原最新单季、上季、去年同季的**同长度期间**，使同比和环比真正可比。很多 10-Q 仅披露年初至今累计，**Q4 单季＝本财年12个月累计－9个月累计；Q3 单季＝9个月累计－6个月累计；去年Q4＝去年12个月累计－去年9个月累计**。单季数必须逐项从**同一财年、同口径**的两份官方原始表相减，标注「单季度按累计现金流差分计算」，必要时解释分类调整；缺任一来源时不猜，标「无法可靠计算」，且不能拿全年的现金流与单季利润直接对比。
   - **资产负债表**：这是期末**时点存量**，取「最新季末 Q4 / 上一季末 Q3 / 去年同季末 Q4」。对资产、负债、现金、存货等计算「同比＝最新余额与去年同季末余额的变化」「环比＝最新余额与上季末余额的变化」。明确它们是**余额变化**而不是一段期间的收入增长。若只有年末与上年末数据、缺少上季末，则环比写「无法取得／不适用」，不可用年度变化冒充环比。
   - **计算口径**：通常同比＝（最新值－去年同季值）÷去年同季值，环比＝（最新值－上季值）÷上季值；比率行（毛利率／净利率／流动比率）优先展示百分点或倍数变化；基期为零、负数或由负转正时用**绝对金额差或「转正／转负」**解释，不输出误导性的增长百分比。特殊会计口径与无法比较要就近标明。

4. 使用报表列报的口径及单位；不能把百万美元误写成亿美元。合并与分部、归母与总净利润、现金及受限现金、短期投资、借款与租赁负债均要区分。会计准则不同时尊重原表分类。
5. 若行业或财报格式特殊（例如银行、保险、REIT），仍只读三表，但按真实报表项目调整关键行；不强行用工业企业的存货、自由现金流或流动比率评判银行。

## 新人可点击展开的会计术语解释（强制）

**目标是用户在 GitHub 仓库的 Markdown Preview 里能够真实操作，而非只看见一个 ⓘ 装饰图标。** GitHub 可能移除 `<abbr title="...">` 的部分 HTML 属性，之前的鼠标悬停说明可能完全失效。**不要继续使用 title/abbr 作为唯一解释机制**。

在三张 Markdown 表格**第一列的每一个财务项目**，使用 GitHub 官方支持的原生可展开标签：

```md
| <details><summary>折旧与摊销加回 ⓘ</summary>买设备时现金可能早就付出；会计按使用年限逐期记折旧，让当期利润减少。但本季度没有为“这笔折旧”再次付现金，所以从净利润算经营现金流时加回来。不是公司新收到的钱。</details> | 34.50 | 33.20 | 31.27 | +10.3% | +3.9% |
```

- **点击展开，不依赖鼠标悬浮**：鼠标点击项目名或其左侧的展开箭头，解释应在同一表格单元格里直接出现；再次点击可收起。Mac 和 Windows 的桌面浏览器操作相同；触屏通常也能点击。
- **只用原生 HTML**：使用 `<details><summary>项目名称 ⓘ</summary>通俗解释</details>`，不使用 JavaScript、CSS、弹窗插件、`<abbr title>`、依赖 hover 的 `title` 属性或不稳定的自定义事件。GitHub 文档确认 `details/summary` 支持点击展开；表格内的嵌入方式须验证：保持单行、所有标签完整闭合，不能让 HTML 将 Markdown 表格截断。
- **每行都有解释**：利润表、现金流量表、资产负债表所有列出的**每一个项目**都必须带展开说明。会计名词尤其说明实际含义、为什么加回或扣减、正负数代表什么，以及容易误解的地方。
- **解释不敷衍**：例如「折旧与摊销加回」要说明设备可能早已付款、费用在利润表按期确认、当季不重复付现金，因此计算经营现金流时加回；「存货变动的现金影响」负数不是公司亏损；「股权激励费用加回」不是公司收到新现金。每条约 30–100 汉字，不能仅重复项目名称。
- **兼容与降级**：如 Markdown 渲染器不支持在表格中折叠，至少第一列能直接显示**可阅读的中文解释**。如果实际 GitHub 页面仍无法展开，应改为第一列可点击的原生 Markdown 脚注或直接增加可见解释，不再反复尝试悬停属性。不要声称通过本地语法测试就证明用户的 GitHub 页面一定能点击。
- **保留数据**：所有项目值、同比环比、期间、三张表和单文件保存规则保持不变。提交后逐行检查 3 张表的所有项目都有非空解释，并进行 GFM 表格语法校验。必要时在三个表前加一句「点击项目名称展开通俗解释」。

## 公司专属重点指标：关键数值标红（强制）

**目标：用户不必读懂几十行财务科目，只看三张表里的红色数字，就知道这家公司本季度最应该关注什么。红色表示“重点阅读”，不表示利空、亏损或异常；重要的正面和负面数据都要标红。**

### 如何选择重点，而不是所有公司套同一个模板

1. 先从财报及必要附注识别行业、实际收入来源、主要成本、经营阶段（成熟盈利、快速增长、持续亏损、资本密集扩张等）及本季主要财务变化。问自己：哪些数字最能说明这家公司是否健康？哪些数字可能改变对利润、现金或偿付能力的判断？
2. 每张表通常选 **3–6 个重点项目**（特殊情况可到7个，并在表后说明原因）；项目较少时酌减，不能为了凑数标红，也不能把整张表染红。保留其余原始数据和同比环比作为背景，不删除非重点行。
3. 重点应同时包含长期核心指标和本期值得特别关注的变化，例如利润率恶化、现金流转正、异常营运资金占用、债务快速增加、资本开支激增或一次性事项。不能只按金额最大、涨跌幅最大或数值为负自动选取；小基数高增幅未必重要。
4. 以下为选取思路，不是固定清单；只选公司适用、当期可从三表或必要附注核实的项目，不编造数字，不引入股价、估值、预测或额外报表。比率须解释口径，必要时由原表计算。

| 公司类型 | 利润表重点候选 | 现金流量表重点候选 | 资产负债表重点候选 |
|---|---|---|---|
| 保险（如 LMND） | 毛已赚保费、净已赚保费、毛/净赔付率、保险成本、净亏损；留意再保险结构 | 经营现金流、应收保费、未到期保费、未付赔款变动、借款净流入；适用时简化自由现金流 | 现金及投资、应收保费、赔款准备、融资借款、股东权益；必要时核查法定资本披露 |
| 航天及高增长制造（如 RKLB） | 收入、毛利率、研发费用、营业亏损 | 经营现金流、资本开支、自由现金流、合同负债变动、增发净收入 | 现金及短期证券、合同资产、存货、债务、流通股数 |
| 成熟消费科技（如 AAPL） | 收入、毛利率、营业利润、净利润、摊薄每股收益 | 经营现金流、自由现金流、资本开支、股票回购 | 现金及有价证券、债务、存货、应收款、权益（结合回购） |
| 软件/SaaS | 收入、毛利率、营业利润率、净利润 | 经营现金流、股权激励加回、递延收入变动、自由现金流 | 递延收入、现金及投资、应收款、债务、商誉（如有重大并购） |
| 半导体及重资产制造 | 收入、毛利率、研发费用、营业利润 | 经营现金流、资本开支、自由现金流、存货占款 | 存货、固定资产、在建工程、现金、债务 |
| 银行 | 净利息收入、净息差、拨备费用、净利润 | 按银行真实现金流分类关注存款、贷款及融资变动，不用工业企业自由现金流评价 | 贷款、存款、不良贷款、贷款损失准备、资本充足率（附注适用时） |
| REIT及房地产 | 租金收入、经营费用、利息费用及适用的FFO（明确非GAAP及调节口径） | 经营现金流、物业资本开支、分红、借款净变化 | 投资性物业、现金、债务及到期结构、权益 |

### GitHub Markdown 表格里怎样标红

- **红色要落在数字单元格上，不仅仅给项目名加粗。** 对选中的每个重点行，至少标红本季数值，同时默认标红其有意义、可比的同比和环比数值；上季及去年同季保持普通数字，若历史基准本身是判断关键（如亏损转正）也可标红。没有披露或不可比的值不伪造、不标红。
- GitHub 原生 Markdown 通常会过滤 HTML 的 style/color 属性，不依赖 span/style、font color、JavaScript、额外 CSS 或外部图片。优先采用 GitHub 支持的行内数学渲染 MathJax，用 $\color{red}{\mathbf{65.00\%}}$ 将数字标成红色粗体（百分号须写作 \%；负号、正号、小数和精度保留）。纯数值可用 $\color{red}{\mathbf{7.3}}$；带百分点等中文单位时仅把数字放进数学表达式，单位留在外部，例如 $\color{red}{\mathbf{+3.00}}$ 个百分点。转正/转负说明也留在表达式外，不改变原数值。
- **强制兼容标记**：在重点行原有 summary 项目名前加 🔴，保留点击展开解释；普通行不加红点。这样即使数学颜色在某个 Markdown 渲染器失效，仍能识别重点。如果实际预览不支持数学颜色或显示原始公式，必须改成普通 Markdown 粗体数字（如 **65.00%**），保留红点，不让未渲染的公式妨碍阅读。GitHub [行内数学文档](https://docs.github.com/zh/get-started/writing-on-github/working-with-advanced-formatting/writing-mathematical-expressions) 说明了数学渲染支持，但不保证所有预览器或表格中的着色都正常；不能仅凭语法检查声称实际显示已验证。
- 三张表各自表前原有的一句说明中加入「🔴/红色数字＝该公司本期重点关注项，不代表好坏；点击项目名称展开解释」。重点项目的折叠说明在原有通俗解释之后补一句「为什么重点看：……」，结合该公司实际风险、经营变化和对应数值解释，不写泛泛定义。表后原有2–4句分析优先解读标红指标，指出越高还是越低通常更好以及何时例外。
- 保持每行单行、六列结构、details/summary标签闭合；不增加第四张表、额外章节、独立图例表或评分，不改变财务口径、单位、原始数值及同比环比算法。

示例（LMND 2026 Q3，金额为百万美元，演示重点标记与普通行的区别，并非要求每家公司选同样的指标）：

~~~md
| 项目 | 2026 Q3 | 2026 Q2 | 2025 Q3 | 同比 | 环比 |
|---|---:|---:|---:|---:|---:|
| <details><summary>🔴 毛赔付率 ⓘ</summary>每100美元毛已赚保费对应多少赔款及理赔费用。为什么重点看：LMND保留更多承保风险，本季赔付率由60%升到65%，需关注承保质量。</details> | $\color{red}{\mathbf{65.00\%}}$ | 60.00% | 62.00% | $\color{red}{\mathbf{+3.00}}$ 个百分点 | $\color{red}{\mathbf{+5.00}}$ 个百分点 |
| <details><summary>分保佣金收入 ⓘ</summary>再保险商按合同支付的佣金，可补偿获客及保单管理费用。</details> | 17.4 | 20.4 | 32.2 | -46.0% | -14.7% |
~~~

交付前必须检查：三个表都已经按该公司经营特点选出少量重点，而非仅标红亏损；重点行本期数字及适用的变化数字有红色数学标记或兼容的红点加粗降级；普通行不误标，所有标记去除后原始数值完全不变；重点解释讲明为什么这家公司应该看这个数。能检查实际 GitHub 渲染时检查，无法检查时在最终聊天说明限制。

## 第二步：只做三张易读的表

**最终报告只允许一个 H1 标题和以下三个 H2 章节；每章一张 Markdown 表格，合计三张。每行项目名都要有 `<details><summary>项目名称 ⓘ</summary>通俗解释</details>` 可点击展开说明。三张表都须以「最新季、上季、去年同季、同比、环比」为默认列。** 每张表必须按公司专属重点规则标红关键数值，并保留 🔴 兼容标记。表格前最多一句话解释本表作用及重点图例，表后 2–4 句通俗分析，不产生额外总览、总结、第四张表、资料附录。

### 1. 利润表｜面子：卖了多少，最后赚了多少？

表格格式：`项目｜本季｜上季｜去年同季｜同比｜环比`；表格上方注明各列的**真实日期范围、币种、单位**，比率行可以用百分点差。

优先从原表选择（按企业适用性，不机械凑项目）：**营业收入、营业成本、毛利润、毛利率、研发及销售管理费用、营业利润、税前利润、净利润、归母净利润（适用时）、摊薄每股收益**。

表后必须回答：
- **同比和环比**看收入和净利润分别发生了什么变化？**收入增长不代表利润增长**，而且节假日促销等季节性可能导致同比与环比呈现相反方向。
- 毛利或营业利润是否改善？有没有明显一次性事项影响利润？
- **一句话结论**：面子是变好、变差还是证据不足，并说明一个最重要的理由。

**例子仅用于解释口径**：卖出 100 元商品，直接进货／生产花 60 元，毛利润是 40 元；尚未减研发、工资等费用，绝非净赚 40 元。不要把假设写成公司真实数值。

### 2. 现金流量表｜里子：赚到的钱进账了吗？

表格格式：`项目｜本季｜上季｜去年同季｜同比｜环比`。**必须优先以三季单季现金流填表**；仅有官方累计披露时按上一节的差分公式计算并写明来源，如确实无法还原单季度，才改用已公布的累计期间，并**在无法对比的列标出不可比**。

重点列（在公开表里适用时）：**净利润（用于现金桥接）、经营活动现金流（CFO）、主要营运资金变动（应收、存货、应付等，选最关键项）、资本开支现金支出（CapEx）、简化自由现金流（FCF = CFO − 支付的固定资产购置款）、投资活动现金流、筹资活动现金流、回购／分红、借款净变化、期末现金及现金等价物的相关勾稽信息**。将非现金的股权激励加回（SBC）与实际现金收入区别对待。

表后必须回答：
- **同一季度的净利润与经营现金流匹配吗？** 同比和环比分别怎样变？为何差距变大／变小？注意利润是权责发生制。
- **经营现金流支付资本开支后还有多少？** FCF 只能作为**明确定义的简化口径**；银行或其他不适用行业不硬算。
- 钱主要花在扩大业务、还债、回购／分红，还是靠借新债／卖资产维持？**负的投资现金流不自动等于经营很差；正的筹资现金流不自动等于赚钱**。
- **一句话结论**：里子是否比面子扎实，说明最重要的现金证据。

### 3. 资产负债表｜底子：账上有什么，承担多大负担？

表格格式：`项目｜本季末｜上季末｜去年同季末｜同比余额变化｜环比余额变化`。表头写明**三个具体期末日期**；这是期末余额之间的变化，不是单季度现金流。同比、环比优先用金额变动或适当的比例、百分点，注意基数和符号。

重点列（按公司报表适配）：**现金及现金等价物、短期可变现投资、应收账款、存货、流动资产、固定资产／无形资产／商誉（必要时）、资产总额、应付账款、流动负债、短期债务、长期债务、总负债、股东权益**。列出必要的**净现金或净债务**计算依据时，必须说明含哪些债务／投资，不混同现金与受限现金。

表后必须回答：
- 账面现金等较易动用的资金能否覆盖短期到期负担？若需要，计算流动比率或净负债，但解释局限。
- **应收和存货同比、环比分别变化多少？** 有没有异常堆积？资产负债表是否支持前面的利润和现金质量判断？
- 长期债务、商誉、股本或权益变化中哪一项最值得注意？**股东权益为负不自动等于破产**，还需看现金创造能力和实际偿债安排。
- **一句话结论**：底子扎实、紧张还是尚不能判断，并说出决定性的事实。

## 三表之间必须核对的关系（研究步骤，不新增第四章）

- 利润表净利润 → 现金流量表经营现金流：找非现金费用和营运资金变化，而不是假设相等。
- 现金流量表期末现金 → 资产负债表现金：注意**受限现金、币种折算及现金流量表列报口径**，不一致时解释，不强行对齐。
- 资产、负债、权益满足 **资产＝负债＋股东权益**（合并报表有少数股东权益时按原表科目）；核对总计避免错抄。
- 所有自算同比、环比、差额、毛利率、FCF 都可复算；三张表的比较必须**同长度期间、同币种、同会计口径**。基期为负或零时避免误导性的增长百分比，用绝对变化和解释代替。
- **只用已发布数据**；缺项写「未披露／无法确认」，不从其他公司、历史估算、市场预测或未经证实网站补造。
- 三张表的**各自关键判断应能相互解释**，但不另外生成总结表。
