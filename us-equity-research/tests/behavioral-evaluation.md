# 技能验证与行为评测

结构测试验证包的可加载性、引用、可移植性和约定的报告布局；它不验证投资判断。行为评测必须保留模型实际回答，再由评测者对照标准检查，不能根据指令中出现某句话就判通过。

## 运行结构测试

从仓库根目录运行（需安装 uv；PyYAML 放入 uv 管理的依赖环境，不修改系统 Python）：

```sh
uv run --with pyyaml python -B -m unittest discover -s us-equity-research/tests -v
```

已有包含 PyYAML 的 Python 环境也可以直接运行同一 unittest 命令。测试只约束本技能包，不要求相邻技能目录为空。财务表测试不绑定示例年份或说明文字。

## 准备与执行行为评测

1. 用标准库脚本创建新的评测目录；路径已存在时拒绝覆盖：

   ```sh
   python3 -B us-equity-research/tests/prepare_behavior_eval.py /tmp/us-equity-eval-run-01
   ```

   目录包含冻结的 `skill/`、仅含题目的 `inputs.md` 和记录题号及 SHA-256 的 `manifest.json`。不包含验收答案或过去结果。

2. 让新上下文中的模型或独立子代理读取上述包，执行指定案例。只提供技能、输入和下面的任务提示，不提供预期答案、疑似问题或修改历史：

   > 使用 packet/skill/SKILL.md 及其参考文件，完成 packet/inputs.md 中指定案例。所有资料为离线虚构数据，不联网、不补充真实公司资料。按各题请求输出实际回答；用 `## Case N` 分隔并保存到 packet/responses.md。过程题说明执行过程，章节题输出章节。不要读取验收标准、其他运行结果或自行评分。局部请求按用户明确范围执行，不自动扩成整篇报告。

3. 评测者另读 `behavioral-cases.md` 的验收标准，逐题核对实际输出，包括公式、单位、日期、证据边界、缺失信息处理及展示结构。允许同义表达和合理舍入；不强制文字完全匹配。出现事实编造、口径混用或关键计算错误判失败；未完成或证据不足记未评测，不能算通过。
4. 保存输入清单、文件哈希、原始回答和逐题评审。评审记录执行日期、执行器/模型（可得时）、样本次数、案例范围、通过/失败/未评测、实际证据与局限。回答或评审不能事后改写成“成功样例”；修复后新建一次运行，保留旧失败。
5. 比较修改前后时使用同一输入与同一评分标准。基线已经通过的案例只能说明本次抽样未退化，不能宣称修复了已观察到的行为错误。必要时对高风险或不稳定案例多次独立采样，报告通过次数，不把一次通过解释为稳定成功率。

案例 19 检查完整深研的执行计划与交付边界，不证明已完成真实公司研究、联网核验或文件交付。案例 20 要从混合原始归档实际发现与筛选事件，并产出正文和底稿；不能只复述研究计划。案例 21 检查来源缺口下的完成声明。评审须检查遗漏事件和未经支持的覆盖声明，不能只统计表格行数或关键词。整套离线案例不能代替真实来源条件下的检索验证，也不能证明无遗漏。
