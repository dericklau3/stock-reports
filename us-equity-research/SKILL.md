# 美股个股研究

## 唯一研究模式：深度个股研究

研究美股上市公司，包括在美国上市的外国发行人及 ADR。每次公司研究都产出一份截至指定日期的**完整中文深度报告**。首次研究、重新研究、财报发布后或重大公告后重新评估，均使用同一深研流程与模板；财报和事件是研究输入，不另设财报后追踪或事件简报模式。

旧版研究结论应从 `tracker.md`、`research-records/` 或 Git 历史提取，当前唯一报告和这些记录不能代替本次核验，也不能把重新研究降级为只更新 tracker。**每个股票代码在仓库当前分支中只能保留一份深度研究报告；重复研究完成后替换旧报告，不累积旧版报告文件。**对已完成报告的明确解释、纠错或局部修改按用户指定范围处理，不额外发明一种研究模式。技能不授权交易、发消息、发布报告或创建定时监控。

## 核心研究要求

- 不编造财务、市场预期、新闻、引文、业务进度、成功概率或估值区间。区分事实、管理层目标、研究假设与观点。
- **第1节业务讲解必须默认折叠显示。** 先明文写一句公司整体定位；每条已确认收入的业务（含「其他业务」中有实质经营的子业务）分别用独立的 `<details class="business-detail">` + `<summary>` 包住详细收款链和对应举例假设，**不写 `open` 属性**。`summary` 用通俗业务名称及可核实的简短收入信息，读者按需点击展开；最新季收入结构表、同比/环比说明、合并收入对账和竞争/利润判断保持直接可见，绝不整体折叠整章或把所有业务塞入一个折叠项。具体标记、Markdown 空行与渲染验收以[报告模板](references/report-templates.md)为准。
- **每个正在贡献已确认收入的业务，都要分别讲清楚它如何赚钱。** 先由最新财报列出全部报告收入分部及披露的实质性子业务（包括合并在「其他业务」中的可辨认业务）；按每项业务分别说明「实际卖什么 → 解决什么客户问题 → 谁采购、谁付款、最终谁使用 → 如何收费及何时形成会计收入 → 主要成本及利润/亏损来源」，并分别给出有明显「举例假设」标识的交易链示例。不能因为两类业务均销售芯片就合并为一个泛泛的模式；不能只讲最大的两项、只在一张收入表写其他业务名称，或仅用两项示例应付所有业务。真实客户及交易须有来源，不编价格；术语首次出现解释，合作方/渠道/付款人不可混淆。
- 对「其他业务」向下查真实持续经营的组成（如子公司/产品线），**单独解释其商业模式**；已出售/终止合并的历史业务要明确不属于当前持续合并收入，初创/规划业务未证实收入时单列标注，未单独披露金额不能编数。
- 解释竞争优势必须有客户选择、定价、留存、成本、份额或替代方案等证据，不能仅靠公司自称领先。多业务公司区分当前利润来源、消耗资金的业务和尚未验证的商业化。
- **第2节重大事件必须按月份分组为横向 Roadmap 事件卡片，点击弹窗查看详情。** 每个 YYYY-MM 月份对应一列，下方纵向堆叠该月全部已核实的A级独立事件；事件卡片仅显示标题与一句话摘要，详情保留精确公告日、不同的实际发生/签约/交割日、关键条款、真实影响、原始来源。报告 Markdown 按[报告模板](references/report-templates.md)输出固定 `event-roadmap` / `event-month` / `event-entry` 标记（使用原生 `<details>` 做非 JS 环境的可展开备选），网站将卡片点击映射到原生 `<dialog>`。**不得再生成第2节的三列表格**；此变化仅改变呈现方式，不减少核查范围或漏掉重大事件。
- 在估值前呈现已公布重大事件与真实经营进展。公告日和不同的发生日分别记录，附原始来源；签约、交付、付费、收入、利润与股东现金回报分别判断。
- **强制完整核查并列示收入分部**：先从最新适用财报分部注释、MD&A及业绩附件取得全部报告分部、其他业务及重要披露子业务，不可只介绍主要产品。逐项列收入金额、去年同季、紧邻上一季及最新季，并在同一张收入结构表内同时展示同比（YoY）与环比（QoQ）。在表格紧邻位置用通俗中文解释两者各在比较什么及计算公式；同比主要看跨年变化，环比主要看近期变化。季度资料缺失或口径不可比时明确标注，不得推算。注明报告层级（分部、子项、小计）、更名和重组。包括增长快、正在亏损或金额较小但单独披露的业务。列出内部交易抵销、核验外部实际收入，并与合并收入对账；不造未披露数字，不双计小计。具体方法详见[数据核验](references/data-verification.md)与[报告模板](references/report-templates.md)。
- 财务采用适用的申报与公司 IR；按原始会计准则标注，调整后指标另列口径。检查利润到现金的转化、资本投入、SBC/稀释、可用现金、债务到期、融资、客户集中与管理层兑现。
- **第6节必须优先给出一个明确、可复算的当前合理价格参考估计（美元/股），不能只罗列倍数与风险却拒绝估价。** 以当前股价、真实经济股数、已实现TTM财务、净现金/债务为底，首选**公司自身最近四个完整财年的历史实际估值倍数中位数 × 目前已实现业务规模 + 净现金，再除经济股数**；选择适用P/E、EV/Revenue、P/B或资产净值锚点，保留样本和口径。**仍排除同行比较和未来DCF**。历史倍数映射是有条件的估值研究，不是客观精确的内在价值；不可凭空给倍数或强行编价。
- 区分好公司与好价格。最强反证、当前定价的脆弱点和可观察的改判条件必须进入研究；缺乏证据时说明具体影响，不用精确数字填空。
- 默认报告只包含七个实质章节，不设置独立“四位投资视角”或“未来关注事件”。客观经营证据、反方观点及后续验证分别归入现有章节，不用主观评分机械生成买卖或仓位指令。

## 执行流程与必读资料

1. 确认发行人、代码、交易所、股份类别、财报期间和研究截止时间；有旧研究时先读旧报告及 `tracker.md`，列出须重新核实的关键假设。
2. 读取[数据核验](references/data-verification.md)，确认截至研究时点最新的适用财报、报价、期后公告和股本变化；建立关键来源及口径记录。
3. 从最新财报盘点收入分部、重要子业务及「其他业务」具体组成；对**每条已形成收入的业务逐项完成完整收款链讲解与交易例子**，再调节至合并收入、解释竞争环境。读取[公司类型与条件检查](references/company-types.md)，按实际行业、阶段与证券结构选择指标，不把软件或制造企业指标硬套给所有公司。
4. 读取[已公布重大事件](references/announced-material-events.md)，按「明确时间范围 → 列出关键主体 → 建立候选事件清单 → 核验与筛选 → 正文呈现」核查近 12 个月，补充更早但仍影响投资逻辑的事件。在底稿保存实际时间与来源覆盖、候选事项及取舍理由；不能找到几条新闻就停止，或用正文行数限制检索。**先按A重大/B经营进展/C普通或未核实分级，只有A进重大事件路线图；B中只有影响核心投资假设的重点事项可进第3节，普通合作、送样、施工等只留底稿，不能因合作名气或新闻数量升格。**公告日期、内容、实际意义及原始来源在正文单独呈现。
5. 读取[经营事项与执行进度](references/operating-agenda-execution-progress.md)，**优先筛选真正影响未来收入、利润、现金、核心客户、竞争地位或监管准入的少量重点事项**，核对原始承诺、最新证据、已完成节点、重大延误与下一关（含有证据的预计日期或日期未披露）。第3节合并经营进展和未来关键验证，只写实质事项，不收录例行小新闻，也不在第2节重复重大公告。
6. 研究第6节时读取[估值规则](references/valuation.md)，复核当前股价、实际TTM收入/利润/毛利、现金、债务、经济股数；寻找**本公司自身至少三个有效历史同口径估值观察值，首选最近四个完整财年EV/Revenue中位数**，以实际TTM和同一时点净现金/债务桥接计算**一个明确的合理价格参考（$X.XX/股）**，并核查历史样本与股本时点差。稳定盈利、金融或净资产企业按其经济性质改用自有历史P/E、P/B或可核实NAV。计算适用的当前倍数与市价相对该估计的价差。**不做同行比较、不做未来DCF**；只有可用历史/资产/盈利锚点均缺失时才明确不能可靠量化，且应说明阻断的证据。程序复算并保存来源、样本、输入和输出。
7. **记录与复盘：**对已实现的财务、资产负债表、股数和价格记录来源与时点，保存实际倍数的计算输入和结果。旧P0/P1/P2与历史DCF快照只作为历史归档，避免覆盖或将其旧预测重新写成最新估值；本次研究不调用这些远期引擎。
8. 采用[完整深研报告模板](references/report-templates.md)生成**七章节**报告：第3节合并重点经营进展与下一验证，删除独立未来事件章节和四位投资人视角章节，最后以主要投资风险收尾。只有用户另行明确要求四位视角对比时，才参考[四位投资人视角（可选）](references/investor-lenses.md)单独回应，不在默认研究正文追加。
9. 完成下方验收，保存完整报告和底稿，更新 `tracker.md` 的当前状态与历史变化。

## 报告结构与去重

### 投资观点标签与网页顶部展示

- 每份报告开头和 `tracker.md` 的 `## Current Research View` 第一行，**必须使用相同的、可独立提取的简短标签**，格式为 `- **投资观点：**中性偏谨慎。<一句简要理由>`（报告也可不用列表符号）。先写标签、再以句号分隔一句依据；**标签不应是一整句话或一段估值报告**。可按证据采用「看多／看好」「中性偏建设性」「中性」「中性偏谨慎」「谨慎观察」「看空」等清楚且有方向的表述；尚无法得出可靠方向时明确写「研究中」，不得把资料不全冒充「中性」。严禁为了统一标签而凭空制造更积极或更消极的结论。
- **股票详情页顶部只显示投资观点标签和简短的含义说明，并提供按需展开的观点术语解释。** 不在顶部复述 `Current Research View` 整段文字，不堆放研究截止时间、财报来源、证券身份、历史版本差异、估值公式、模型价差、内部文件路径等。完整核验信息继续保留在报告对应章节、`tracker.md` 与研究底稿中；只精简网页头部，不删除研究事实。该要求也适用于重新研究后的网站更新。
- 观点释义遵循：**研究中**＝未形成标准化方向标签，不等于中性；**看多／看好**＝研究判断偏积极而非承诺上涨；**中性**＝正反证据交织，暂不明确看多或看空；**中性偏建设性／偏谨慎**＝以中性为基础但稍偏积极／防守；**谨慎／看空**＝更加关注风险或判断负面。上述标签不是交易指令。


[报告模板](references/report-templates.md)是正文格式的唯一规范来源；专门参考文档说明如何研究。入口不再重复全部表格。默认用通俗中文，每个章节只增加新信息，正文精简不等于省略核查。

完整报告的七个章节、表格、摘要和结尾统一遵循[报告模板](references/report-templates.md)。**三项开头结论结束后直接进入第1节，不写研究截止日、财报期间/发布时间、报价时区/交易状态、股份类别和原始链接集合的说明段**。这些元信息保留于 `tracker.md` 和研究底稿；必要的财务期间、价格日期及证据来源仅在对应收入、财务、估值或事件处注明。第3节只保留真实影响投资逻辑的重要在建项目、实际执行证据和下一道验证；普通消息存底稿。不设独立未来事件表或四人视角章节。关键来源链接靠近对应事实，重要缺口在相关章节说明；详细核验、计算和历史记录保存在底稿。

## 重复研究与证据可信度

每次重新研究都核实新财报、公告、报价、股数和旧预测是否仍成立；未变化且仍有效的事实可以复用，注明原来源及本次核查。不能用旧股价、旧共识或旧目标期冒充当前数据。

在底稿中对关键变化记录「上次假设与日期 → 新事实及来源日期 → 本次假设 → 估值/观点影响」。区分股价、盈利、经济股数、净索偿、估值方法与倍数的变化。首次覆盖没有旧基线就建立基线，不虚构上调或下调。旧估值失效时必须重算；缺输入则明确该情景无法可靠估值，不静默沿用。

证据可信度与商业质量分开判断。市价、实际TTM、股本、现金/债务与历史经营数据越完整，当期估值描述越可信；当前交易倍数本身不能证明内在价值；以本公司历史实际交易倍数与当前已经实现的业务规模计算的合理价格，是有选样与资本结构限制的**参考估计**，要展示依据，不伪称唯一真值。未核实合同、现金、股数等关键事实须具体披露，不打置信度分数。

## 保存完整研究

除非用户明确不保存，使用 `research/COMPANIES/TICKER/`，代码大写：

- `deep-research/YYYY-MM-DD-deep-research.md`：**每个 TICKER 只保留一份最新的完整深度研究报告。**首次研究按日期创建；重新研究同一股票时先读取当前报告与历史记录，重新生成最新完整报告。若同一天已有报告，**原位更新**，禁止新增 `-v2`；若日期更新，保存新日期报告并将旧的 `deep-research/*.md` 报告删除，确保最终恰好保留最新一份。报告删除应在新报告成功写入、底稿及 tracker 更新后执行；尽可能用原子提交确保仓库无中间缺档状态。历史研究关键变化仍保存在 `tracker.md`、`research-records/` 与 Git 历史，不删除这些证据底稿。
- `research-records/`：按研究日期保存必要的来源索引、计算与重要假设，格式按任务需要选择，不强制数据库。报告关键结论应能追溯到这些记录。
- `tracker.md`：**标题下必须有独立一行 `Last updated: YYYY-MM-DD`（本次最新完整研究日期）**，供网站索引提取和排序；**`## Current Research View` 首条必须是与报告一致的 `投资观点` 简短标签，后续才写详细判断与研究元信息，禁止让网站首页/详情页将整节当作观点标签显示**；当前报告链接、研究与估值时点、核心假设、事件日期、原始承诺、风险与下一验证；追加带日期的变化记录，保留历史。不要只写「创建于」或把日期藏在正文中。

既有历史材料可以读取，不迁移或删除。新研究只生成完整深研，不生成独立财报或事件追踪报告，也不以 tracker 更新代替交付。

## 最终验收与交付

交付前核对：

- 研究截止时间、最新适用财报、报价日期/时区/交易时段一致；历史研究未引入截止日后的信息。
- **季度增速验收：**能取得可比季度数据时，业务收入表同时给出去年同季、上一季、最新季、同比和环比；表前或表后紧邻说明同比=与去年同季度比、环比=与紧邻上一季度比，以及对应计算公式；零基数、口径变更、内部交易抵销和不可比期不能硬算或误当作实际增长。
- **折叠交互验收：**第1节每条业务的说明和专属交易例子均在各自默认关闭的 `<details class="business-detail">` 内，使用有效 `<summary>` 标题，无 `open` 属性；公司总览、完整收入拆分表、同比/环比定义与对账以及竞争判断保持可见。逐个检查标签配对、Markdown 解析后正文/链接正常、网页与 GitHub 预览均可点击展开；禁止仅用 Markdown 标题假装折叠，禁止删除细节来达到短页面。
- **收入分部与生意讲解双重验收：**最新财报全部报告分部与其他业务无遗漏；公开的重大子业务有数字或明确未披露；列示同比及可比口径；分部、小计、内部抵销、外部收入均正确区分，合并收入对账完成。**逐项检查每条已产生收入的业务，都有对应的产品/服务、需求、直接付款人、收费/收入确认、成本及专属通俗交易例子**；「其他业务」下的实质经营组成不能止步于名字，尚未产生收入的研发或商业计划不得冒充已收费业务。缺任一实际收入业务的付款路径，即使收入表完整也不算通过。不得为精简省去必要讲解或收入表，无法核实部分必须标明。
- **重大事件路线图验收：** 第2节默认输出 `<div class="event-roadmap">`；按公告日月份 `YYYY-MM` 升序排列 `<section class="event-month" data-month="YYYY-MM">`，每月一列，同月A级事件分别输出 `<details class="event-entry">`，卡片短标题/一句摘要、详情完整事实与直接来源均在；无 `open` 属性、所有 HTML 标签正确闭合。精确日期未知时明确未核实，不编月份；同一事件后续披露应注明不同日期并按实际需要合并，不能随意丢弃。网页端点击卡片打开 `<dialog>`，关闭、Esc、键盘操作有效；GitHub Markdown 预览仍可以原生 `<details>` 查看完整内容；第3节不变。不得输出原三列表格或只留几个事件卡片而遗漏A级事件。

- **第3节重大性与去重验收：**仅收录可能实质改变核心收入、利润、现金、客户、竞争地位、监管或股东权益的重点在建事项；每行说明为什么重要、已取得的可核验进度与下一项决定性验证（含时间证据及是否延期）。普通日常新闻不凑数；与第2节的重大公告不重复叙述，且不另建未来事件表。
- 业务付款路径与竞争判断有依据；重大事件有公告日期、不同的发生日期、来源和状态；失败或取消未被隐藏。
